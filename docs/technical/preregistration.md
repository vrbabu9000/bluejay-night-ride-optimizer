# Pre-registered experiment plan (Phase 3, v1, 1 Oct 2026)

> **PAUSED (12 Oct 2026).** This pre-registration v1 belongs to the paused Phase 3 v1. It is kept unchanged for the record. Its replacement is drafted in `scenario_spec.md` v0.1 (to be agreed). Do not generate data from this file.


This file was written **before any engine or dispatcher exists**. Phase 7 runs exactly this design. Any change after Phase 4 starts gets a dated amendment at the bottom, with its reason, and the original text stays as it is. The scenario files are already frozen: `data/scenarios/grid/manifest.csv` holds 330 content hashes, and `data/scenarios/FROZEN.json` holds the ladder.

## 1. Question
On identical synthetic nights, how much does each dispatcher add over the one below it? The ladder is pooling (A − N), waiting (B − A), coordination (C − B) and information (H − C). Where does coordination pay?

## 2. Players
| Player | When it decides | How it decides |
|---|---|---|
| N | On each request | Nearest van, no pooling |
| A | On each request | Greedy insertion, with pooling |
| B | Every W seconds | Greedy insertion, oldest request first |
| C | Every W seconds | Joint route-selection MILP (HiGHS) |
| H | Once, knowing the whole hour | Offline node-arc MILP; the bracket [incumbent, bound] is reported if it doesn't close |

Rules shared by all players:
- W = 60 s by default.
- B and C share the urgent-request fallback and the reassignment rule (config `dispatch`).

Where each player runs:
- H runs on S1, S2 and the base cell.
- L170 runs A, B and C only.

## 3. Metrics
- **Primary:** *timely passengers served*: passengers picked up within `wait_limit_s` (20 min) and dropped off within `ride_limit_s` (25 min) of pickup. These limits are PROVISIONAL (D-04).
- **Secondary:**
  - P90 wait;
  - modeled overflows (Lyft);
  - abandonments;
  - mean ride time;
  - van-minutes per served passenger;
  - solve time per tick (for C and H).

## 4. Cells
There are 11 cells × 30 replicates. Every cell except L170 changes one factor from the base cell. Replicate r uses the same seeds in every cell (common random numbers).

| Cell | Change from base | Why it's there |
|---|---|---|
| base | none: 5 vans, 30 requests (ρ = 6), Poisson arrivals, β = 0.1/min, month-average direction, capacity 4, hotspot starts | Scenario M, "as served" (D-06) |
| rho4 / rho9 / rho12 | 20 / 45 / 60 requests | Load is the main difficulty knob; rho12 is "as requested" |
| burst | 40% of requests in 18:00–18:10 | The first hour of service may open with a surge |
| beta0 / beta0.2 | β = 0 or 0.2/min | Many O-D tables fit the same margins (identification) |
| campus_outbound | Z08 origins × 1.5 | A 6 pm direction we can't observe |
| cap7 | 7 seats | Capacity is ASSUMED |
| depot | All vans start at the campus depot | Start positions are ASSUMED |
| L170 | 27 vans, 170 requests | Does the ranking hold at real density? |

- **The ρ × W heat map:** cells rho4, base, rho9 and rho12 are each run with B and C at W ∈ {30, 60, 120} s.
- **Equivalent fleet:** player A on the base requests with 5, 6 and 7 vans. These are the same request files with a different fleet, which the stream design guarantees.

## 5. Hypotheses (directional, stated now)
- **H1. Pooling pays at the base load:** A − N > 0 at base.
- **H2. Coordination pays more as load rises:** C − B is larger at rho12 than at rho4. We expect C − B ≈ 0 at rho4, where every policy serves everyone and only the waits differ.
- **H3. Waiting can hurt:** B − A may be negative at rho4. We report it either way.
- **H4. The ranking is robust:** the order of A, B and C at base also holds in the β, direction, capacity and start cells, and at L170.
- **H5. Headroom:** H − C is reported as a bracket, with no directional claim.

## 6. Decision rules (fixed now)
- **Paired comparisons:** the per-replicate difference between two players on the same night.
- **Confidence intervals:** 95% paired bootstrap (10,000 resamples of replicates), plus the paired mean.
- **Minimum meaningful gain:** +1.0 timely passenger per hour at base. That is about 3% of the ~37 passengers in a base night, and a smaller gain is reported as "no practical difference" even when the CI excludes 0. Other cells use the same 3% relative threshold.
- **Maximum acceptable harm:** a policy that wins on the primary metric is flagged if, at the same time, its P90 wait worsens by more than 2 min or its overflows rise by more than 1 per hour.
- **Multiplicity:** H1–H4 are the confirmatory tests. Everything else is labelled exploratory.
- **Power check (Phase 7, before the main runs):** if 30 replicates give a CI half-width above 1.0 passenger at base, raise to 60 replicates for every cell. Replicates 30–59 are generated by the same code, without changing 0–29.

## 7. What is frozen before the comparison
- Calibrated values come from Phase 6 (G4), using player A only, and are frozen before any comparison: the travel-time multiplier, the dwell times and the patience median.
- If calibration changes a scenario parameter, the grid is regenerated with the same seeds. The new manifest is recorded here as an amendment *before* any player comparison runs.

## 8. Honest limits, stated in advance
- The maps count completed rides, so the spatial pattern of cancelled requests is ASSUMED to be the same.
- Our baseline A is a stand-in, not TransLoc's dispatcher.
- M (5 vans) is less dense than the real fleet; L170 is the check on that.
- Capacity, start positions, patience and the direction tilt are ASSUMED and varied.
