# M5a: compute benchmark of C (10 Nov 2026)

**Decision:** D-60 (approved 10 Nov). **Plan:** `docs/plans/phase4/plan.md` v2, M5a.
**Status:** run and gated. **Gate passed: M5b runs with 30 nights.** Compute only: no rider outcome was read or tabulated (blind rule).

## What was run
- **Runner:** `src/sim/m5.py` (new), with `tests/test_m5.py` (5 tests).
  - It takes the first hour of a frozen L6 night: the first 64 rows, all with `t_request_s < 3600`, checked against `FROZEN_v2_L6.json`.
  - Each run is in a fresh process, which keeps the peak-memory figure per night.
  - Runs can resume; a different code fingerprint or configuration is refused, not mixed.
  - The dispatcher (`algorithm`) is recorded in every manifest.
  - M5b refuses to start until `m5_preregistration_2026-11.md` exists.
- **Settings:** C, R0, 5 vans, K = 3, node budget 100,000, threads 1, re-plan 120 s, travel multiplier 1.2. Lyft lag, consent, presence and curb-wait are as in the L5 batch (D-56/D-57).
- **Nights:** L6/base_5 r00, r01, r02, each run twice. All six ran in parallel on this Mac (10 cores).
- **Per-run checks:** `l5_pilot.checks` now takes the L6 hash file and accepts G's status "greedy". This file is not in the simulator fingerprint. Re-checking saved L5 runs gives the same pass results.
- **Code fingerprint** (inputs, engine, dispatch, lyft, greedy, l5_pilot): `8670e44b3619…`.
- **Outputs:** `outputs/sim/m5/m5a/compute.md`, `compute_epochs.csv`, `kcheck.json`. These are git-ignored, so the figures are copied here.

Per epoch, pooled over the three nights (388 epochs):

| | Median | P90 | P99 | Max |
|---|---|---|---|---|
| Open requests | 5 | 11 | 17 | 18 |
| Candidates per van | 26 | 232 | 834 | 988 |
| MILP columns | 130 | 1,160 | 4,170 | 4,940 |
| Solve time, s | 0.16 | 7.9 | 25.7 | 35.5 |
| of which the MILP, s | 0.01 | 0.03 | 0.14 | 0.17 |

- **Every main solve was optimal.** The final gap was 0 everywhere, and branch and bound needed 1 node at every epoch.
- **Ties:** unique 375, tie 11, enumeration incomplete 2 (r01 at 3,530 s and 3,600 s). In those 2 epochs the canonical choice among equal-cost plans is not guaranteed; it is not a solver failure.
- **The cost is candidate generation, not the MILP.** Candidates took 97% of solve time (716 of 737 s on r01).
  - Every subset of ≤ 3 open requests was feasible on every van, so counts follow 1 + n + C(n,2) + C(n,3). At n = 18 that is 988 per van.
  - Run time therefore grows roughly with the cube of the open backlog. That explains why r01 takes 11× longer than r00.
- **Cap:** in 142 of 388 epochs some van's chosen plan used the full K = 3.

## K = 4 coverage (planning measure)
- **Sample:** 8 epochs from r00, chosen by a fixed rule written before the check ran: epochs where some van used the full K = 3, evenly spaced.
- **Method:** each epoch was solved from the same observation with K = 3 and with K = 4.
- **Result:** K = 4 planned differently in **1 of 8** (at 2,893 s). It used a 4-pickup route, cost 2.1 points less, and left no fewer requests pending. The other 7 plans were identical.
- **Cost of K = 4:** solving took 9–51 s per epoch, against 1–3 s for K = 3, about 15–25× slower.
- **Limitation:** r00 is the lightest night (≤ 8 open). How often the cap binds on heavy nights (r01, up to 18 open) is not measured here.

## What this shows and does not show
- **Shows:** C fits a first-hour, five-van base night, with every solve proven optimal over its candidate set, run-to-run determinism, and a median of 3.6 min per night.
- **Does not show:**
  - **Run time for high load (83 requests) or 6 vans.** M5a covered base nights only, as planned. Because time grows steeply with the backlog, high load may be several times slower. A compute-only probe of one high-load night is advisable before the M5b batch is scheduled.
  - **Anything about rider outcomes, or C vs G.** That is M5b, under criteria frozen before its first run.
- **Fairness note for M5b** (already stated in plan v2): G has no K cap, and C does. The K = 4 result says the cap changed 1 of 8 sampled light-night plans. Its effect on heavy nights is unmeasured.
